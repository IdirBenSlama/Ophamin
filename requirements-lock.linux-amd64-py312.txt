# Ophamin — portable lockfile (Phase A1 / 0.8.3, 2026-05-17)
#
# Scope: this file pins every transitive dependency at the version a
# **fresh** ``pip install -e ".[all,dev,property_test]"`` resolves on
# Python 3.12 + linux/amd64 — i.e. exactly what GitHub Actions CI does.
#
# Use this for byte-equal reproducibility on a Linux box:
#
#   python3.12 -m venv .venv
#   .venv/bin/pip install -r requirements-lock.linux-amd64-py312.txt
#   .venv/bin/pip install -e . --no-deps
#
# To refresh after a coordinated bump:
#
#   docker buildx build --platform linux/amd64 \
#       -f tools/lockfile_emit.Dockerfile -t ophamin-lockfile-emit \
#       --load .
#   docker run --rm --platform linux/amd64 ophamin-lockfile-emit \
#       cat /lockfile.txt > requirements-lock.linux-amd64-py312.txt
#
# Then re-run mypy --strict + pytest + the coverage gate against the
# resulting venv before committing.
#
# Companion files:
#   requirements-lock.darwin-py314.txt   the author's macOS-3.14 venv
#                                         (forensic local snapshot only)
#
# A true multi-platform lockfile (``uv pip compile --universal``) is
# tracked as open work; this dual-file approach is the honest
# intermediate.
